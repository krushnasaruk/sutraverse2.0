# 🚀 Sutras — cPanel Deployment Manifest

This document describes the structure and components included in the `cpanel-deploy.zip` package. Use this as a reference for future builds or manual deployments on **MilesWeb / Cloudlinux** environments.

---

## 📦 Package Contents

The deployment ZIP is based on the **Next.js Standalone Output**, which is the most efficient way to run Next.js on cPanel/VPS.

### 1. Application Core
- **`server.js`**: The entry point for the Node.js application. (Set this as the 'Application startup file' in cPanel).
- **`package.json`**: Minimal version containing only production dependencies.
- **`node_modules/`**: A pruned set of dependencies generated by Next.js specifically for production (much smaller than the root `node_modules`).
- **`.next/`**: Contains the compiled production build (excluding static assets).

### 2. Static Assets (`public/` folder)
- **`public/`**: All images, icons, and static data files.
- **`public/_next/static/`**: A duplicate of compiled CSS/JS for **Apache Static Bypass**. This allows MilesWeb's LiteSpeed/Apache server to serve these files directly without hitting the Node.js process, significantly improving performance.

### 3. Configuration & Security
- **`.env.local`**: The environment variables file containing your Firebase keys and Gemini API keys.
- **`sutraverse2-firebase-adminsdk-*.json`**: The Firebase Admin Service Account key required for server-side auth and file verification.
- **`.htaccess`**: Optimized for cPanel to enable:
  - **Gzip Compression**: Faster loading of text/json.
  - **Browser Caching**: 1-year expiry for static CSS/JS/Images.

### 4. Deployment Triggers
- **`tmp/restart.txt`**: An empty file used to trigger an automatic reload of the Phusion Passenger Node.js process upon extraction.

---

## 🚫 Excluded Components (Do Not Add)

The following items are **intentionally excluded** to keep the package small and prevent data loss on the server:

| Component | Reason for Exclusion |
|---|---|
| `user_uploads/` | Lives externally on cPanel (`~/user-uploads`) to survive redeployments. |
| `public/uploads/` | Legacy folder; replaced by the external persistent directory. |
| `public/pyqs/*.pdf` | Curated PDF database; should be uploaded once to `~/pyqs` and not overwritten. |
| `mobile/` | Contains React Native code; not required for the Web server. |
| `node_modules/` (Root) | Too large (~500MB+); the standalone version handles this. |
| `scripts/` | Development and maintenance scripts; only needed locally. |
| `*.zip` / `*.rar` | Old build artifacts and compressed archives. |

## 🛠️ Next Build Steps

If you need to generate this ZIP again manually, ensure you follow these steps:

1.  **Check `next.config.mjs`**: Ensure `output: 'standalone'` is present.
2.  **Build**: Run `npm run build`.
3.  **Pack**: Run the automation script:
    ```bash
    node deployment/cpanel/pack-cpanel.js
    ```
    This script automatically handles the folder mapping, cleaning, and `.htaccess` generation.

---

## ✅ Post-Deployment Checklist

1.  Extract `cpanel-deploy.zip` into your `public_html` or application root.
2.  Ensure the directory `~/user-uploads` exists and has `755` permissions.
3.  Verify that `server.js` is selected as the startup file in the cPanel Node.js App UI.
4.  Restart the application.
5.  Visit `/api/verify-files` (as admin) to check if the pathing between Firestore and Disk is healthy.
